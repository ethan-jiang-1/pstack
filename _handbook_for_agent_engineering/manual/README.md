## 六章结构

### [定义：把共同问题做扎实](./define.md)（已完成）

1.1 从手头变更到共同问题。
1.2 把事实、假设、意见与未知项分开。
1.3 拿不定主意时，先获得会改变决定的证据。
1.4 把已经足够清楚的意图固定成可执行规格。

### [设计与计划：让工作可兑现、可委派](./design-and-plan.md)

2.1 先把承诺变成可观察的行为。
2.2 设计可实现、可测试的模块形状。
2.3 拆成可以推进、可以交接的小工作。

### [委派与协作：让执行者独立，让责任可见](./delegate-and-collaborate.md)

3.1 为一个工作包准备最小上下文。
3.2 为同一项变更安排人、agent 与会话。
3.3 让并行工作重新汇合并可交接。

### [验证：证明兑现的是承诺](./verify.md)

4.1 建立能让问题显形的反馈回路。
4.2 验证兑现的是不是最初承诺。
4.3 评审变更是否真的值得合入。
4.4 失败时知道应该回到哪里。

### [交付、运行与演进：让变更安全地进入真实环境](./ship-run-and-evolve.md)

5.1 在交付前给出可接受的风险结论。
5.2 从运行信号开启下一轮变更。
5.3 按顺序落地一组变更。

### [让环境变好：把摩擦变成下一轮的优势](./evolve-the-environment.md)

6.1 把反复摩擦变成有证据的改进。
6.2 把教训编码成结构。
6.3 多轮之后收回累积的承诺与上下文。

## 怎么读

1. 先看症状表，找到最接近你现在感觉的一行。
2. 读对应单元，拿走产物模板或判断规则。
3. 只有需要完整方法、例外或第二案例时，再读同章其他单元。
4. 教程是另一条读法，见 [教程地图](../tutorial/README.md)。
